# The Aura — Your Daily Fortune

사주, 서양 점성술, 현재 지역의 날씨를 한곳에서 확인하는 개인 맞춤형 데일리 운세 웹 애플리케이션.

**배포 주소** — https://skalavue-vert.vercel.app

닉네임과 생년월일시, 지역을 한 번 설정하면 매일 통합 운세와 판단 근거를 제공함. 모든 사용자 정보는 브라우저 안에만 저장되고 외부로 전송되지 않음.

처음 접속하면 설정을 채우지 않아도 바로 결과를 볼 수 있도록 시연용 기본값(1999-08-31 12:30 서울 출생, 현재 지역 광주, 예시 Astro-Seek 차트)으로 시작함. 설정 화면에서 저장하는 순간부터는 입력한 값이 우선함.

## 화면 구성

| 경로 | 화면 | 내용 |
|---|---|---|
| `/` | 통합 운세 | 사주와 점성술을 종합한 오늘의 최종 운세. 두 관점의 공통점·차이를 조건부 조언으로 변환 |
| `/saju` | 사주 운세 | 만세력 여덟 글자, 원국 요약, 대운·세운·월운·일진 기반 상세 운세 |
| `/astrology` | 별자리 운세 | 출생 차트, 오늘 트랜짓, 주요 어스펙트 기반 상세 운세 |
| `/daily-life` | 오늘 하루 | 지역별 날씨, 미세먼지, 뷰티 팁, 지금 관측 가능한 별자리 |
| `/settings` | 설정 | 출생정보, 성별, 지역, 온도 단위, 차트 이미지 관리 |
| `/:pathMatch(.*)*` | 404 | 존재하지 않는 주소 안내 |

사주 페이지와 별자리 페이지는 서로의 계산 결과를 참조하지 않음. 두 결과를 합치는 일은 통합 페이지에서만 일어남.

## 실행

```sh
npm install

# API 키 설정 — .env.example 을 복사해 실제 키를 채운다
cp .env.example .env.local

npm run dev     # http://localhost:5173
npm run build   # 프로덕션 빌드
npm run lint    # ESLint + Oxlint
```

`.env.local` 은 `.gitignore` 로 커밋에서 제외됨. `VITE_` 접두 환경변수는 빌드 결과물에 포함되므로, 실제 공개 운영 시에는 서버 또는 서버리스 프록시를 두어야 함.

## 화면 연출

밤하늘 자체를 배경으로 쓰기 때문에, 정적인 그림 대신 계속 움직이는 하늘을 깔았음.

| 요소 | 구현 |
|---|---|
| 은하수 | 성운 띠는 CSS 그라디언트, 별 1,200여 개는 캔버스. 좌하단→우상단 띠를 따라 밀도를 높이고 은백·은청·연보라·라일락 네 가지 별빛을 섞음 |
| 별똥별 | 4~11초 간격으로 한두 개씩 띠와 같은 방향으로 흐름. 머리쪽 번짐과 꼬리 그라디언트를 함께 그림 |
| 시작 화면 | 은하수가 번지며 별이 모였다가 브랜드가 떠오름. 세션당 한 번만 뜨고 건너뛰기 가능 |
| 점수 링 | 화면에 들어오는 순간 0에서 실제 점수까지 차오름(`IntersectionObserver`). 흰 원판 바깥에 밝은 링을 둘러 글자(진한 색)와 링(밝은 색)이 서로 묻히지 않게 함 |
| 설명 박스 | 마우스를 올리면 표면이 밝아지고 살짝 떠오르며 본문 글자가 또렷해짐 |

별 좌표와 별자리 모양은 고정 규칙으로 만들어 새로고침해도 같은 하늘이 나옴.
`prefers-reduced-motion` 을 켠 환경에서는 반짝임·흐름·별똥별·링 애니메이션을 모두 끔.

## 계산 방식

운세 점수와 행운 정보는 난수를 쓰지 않음. 전부 규칙표와 천문 계산에서 나오므로 **같은 사용자·같은 날짜면 언제나 같은 결과**가 나옴.

### 만세력 (`src/utils/manse_calculator.js`)

절입 시각을 연도별 표로 들고 있지 않고, `astronomy-engine` 으로 태양 황경을 직접 구해 판정함.

| 항목 | 기준 |
|---|---|
| 년주 | 입춘(태양 황경 315°)을 해의 경계로 삼음 |
| 월주 | 12절(황경 315°부터 30°씩)의 구간으로 가름 |
| 일주 | 1984-01-31(KST)을 갑자일로 두고 일수를 60으로 나눈 나머지 |
| 시주 | 일간에서 자시 천간을 얻고 시지를 더함 (자시는 23시 시작) |
| 대운 | 년간 음양과 성별로 방향, 절입까지의 거리를 3으로 나눠 반올림한 값이 대운수 |
| 음력 변환 | 삭(신월) 시각으로 월의 초하루를 잡고, 동지가 든 달을 11월로 둠. 13개월인 해에서 중기(황경 30° 배수)가 없는 첫 달을 윤달로 판정 |

**검산**: `md/fortune/manse_test_cases.md` 의 10개 케이스를 대조하는 스크립트를 두었음.

```sh
node scripts/verify-manse.mjs
```

경계값 케이스(입춘 직전 출생, 야자시, 절입 당일)와 음력 윤달 케이스를 포함해 10건 전부 일치함.

> 구현 중 걸렸던 지점: 1984년 동지가 KST 기준으로 자정 직후(12월 22일 01:23)에 들어, 중기 포함 여부를 *시각*으로 판정하면 윤10월이 통째로 사라짐. 달의 경계가 "삭이 든 날"이라는 날짜 단위로 정해지므로 중기도 KST 날짜로 따져야 맞음.

### 사주 운세 (`src/utils/saju_daily_fortune.js`)

일진·월운·세운·대운의 십성을 각각 다른 영향도로 합산함. 일진이 오늘 체감의 핵심이라 가장 크게 봄.

- 십성별 종목 가중치는 `constants/sajuDailyRules.js` 에 표로 분리
- 원국에서 부족한 오행이 오늘 들어오면 보완(+), 이미 과다한 오행이 겹치면 과열(−)
- 행운 정보는 보완이 필요한 오행에서 규칙표로 선정하고, 변형값으로 일진 인덱스를 씀

### 별자리 운세 (`src/utils/astro_daily_fortune.js`)

오늘 트랜짓과 출생 차트 사이의 각(합·육분·사분·삼분·충)만으로 점수를 만듦. 오브가 좁을수록 강하게 반영.

- 행성 황경은 `astronomy-engine` 으로 계산
- 상승궁·MC는 항성시와 황도경사각으로 직접 계산하되, **출생시각과 출생지역이 모두 있을 때만** 만듦
- 하우스는 Whole Sign 방식. Astro-Seek가 쓰는 Placidus와 표기가 달라질 수 있다는 안내를 화면에 표시

### 통합 (`src/utils/integrated_fortune.js`)

종목별로 두 점수의 평균을 내되, 결과 차이를 그냥 두지 않고 성격을 판정함.

- 둘 다 긍정 → 공통 강점
- 둘 다 부정 → 주요 주의사항
- 한쪽만 긍정, 점수 차 20점 이상 → `서로 다른 흐름` 배지와 함께 조건부 조언으로 변환

## 예외 상황 처리

정확하지 않은 값을 정확한 것처럼 쓰지 않는 것을 원칙으로 함.

| 상황 | 동작 |
|---|---|
| 출생시각 모름 | 시주 두 칸을 `미상`으로 두고 여섯 글자로 계산. 안내 문구 표시 |
| 출생지역 모름 | 상승궁과 하우스를 계산하지 않음. 임의 좌표를 대입하지 않음 |
| 차트 이미지 미등록 | 자체 계산 태양 별자리 일러스트로 전환 |
| 설정 없음 | 각 페이지에서 설정 안내와 이동 버튼 표시 |
| API 실패 | 원인별 한국어 문구와 재시도 버튼 |
| 강수 데이터 누락 | `데이터 없음` 과 실제 `0mm` 를 구분해 표기 |
| 아직 밝은 시각 | 관측 별자리 대신 `현재는 밝아서 관측이 어렵습니다` 안내 |
| NASA 검색 결과 없음 | 대체 질의어로 한 번 더 시도하고, 그래도 없으면 안내 문구 |
| 자외선 API 미제공 | 태양 고도와 구름량으로 추정하고 추정값임을 화면에 표시 |

## 데이터 출처를 섞지 않기

미세먼지는 두 기준을 함께 보여주되 출처를 명시함.

- 종합 등급 — 국내 환경부 PM 농도 기준으로 자체 계산
- 참고 값 — OpenWeather가 자체 산정한 AQI(1~5)

등급 이름이 같아도 계산 방식이 달라 어긋날 수 있다는 설명을 화면에 함께 둠.

## 오늘 하루 — 팁과 관측

### 날씨 기반 팁

메이크업·스킨케어와 외출 준비를 나눠 보여줌. 갈래마다 우선순위가 높은 순으로 최대 4개.

| 갈래 | 판단 기준 |
|---|---|
| 메이크업 · 스킨케어 | 습도(건조/다습), 강수, 기온(고온/저온), 미세먼지, 바람 |
| 외출 준비 | **시간당 강수량 5단계**(우산이면 충분 → 장화 권장 → 침수 주의), 강수 예보만 있을 때의 우산 안내, **자외선 5단계 + 야간**, **풍속 3단계** |

자외선 지수는 무료 키로 API를 쓸 수 없어 태양 고도와 구름량으로 추정함. 어떤 값으로 판단했는지 화면에서 펼쳐볼 수 있게 함.

### 관측 가능 별자리와 NASA 사진

대표 별의 적경·적위를 지역 좌표·현재 시각과 함께 계산해 고도와 방위각을 얻고, 태양 고도(일몰 여부)와 구름량·강수를 반영해 관측 가능성을 좋음/보통/낮음으로 가름.

별자리를 누르면 **NASA Image and Video Library**(키 불필요)에서 실제 관측 사진을 불러옴. 별자리 이름만으로 검색하면 로켓 발사 사진 같은 결과가 섞이므로, 그 별자리 방향에 실제로 있는 대표 천체를 질의어로 씀.

| 별자리 | 질의 대상 | 별자리 | 질의 대상 |
|---|---|---|---|
| 거문고자리 | 고리성운 (M57) | 황소자리 | 게성운 (M1) |
| 백조자리 | 베일성운 (NGC 6960) | 물병자리 | 나선성운 (NGC 7293) |
| 사수자리 | 석호성운 (M8) | 처녀자리 | 솜브레로 은하 (M104) |
| 큰곰자리 | 바람개비 은하 (M101) | 카시오페이아자리 | 카시오페이아 A |

별자리 전체가 아니라 그 방향의 천체라는 점을 팝업에 명시하고, NASA 사진만으로는 형태를 알기 어려워 **별자리 모양 그림을 팝업 맨 위에 함께 보여줌**. 황도 12궁 외에 오리온·큰곰·카시오페이아·백조·거문고·독수리 여섯 개의 별 배치를 추가로 그림.

## 프로젝트 구조

```
src/
├─ views/            통합 · 사주 · 별자리 · 오늘하루 · 설정 · 404
├─ components/
│  ├─ common/        내비게이션, 카드 껍데기, 날짜 이동, 점수 게이지, 로딩·오류,
│  │                 은하수 배경(StarfieldBackground), 시작 화면(IntroSplash)
│  ├─ fortune/       세 페이지가 공유하는 운세 결과 컴포넌트
│  ├─ saju/          만세력 표, 기둥 한 칸, 원국 요약
│  ├─ astrology/     차트/일러스트 조건부 표시, 밤하늘 별자리, 차트 요약
│  ├─ daily/         지역 선택, 날씨, 미세먼지, 팁, 관측 별자리, NASA 사진 팝업
│  └─ settings/      프로필 폼, 차트 업로더
├─ stores/           profile · saju · astrology · integratedFortune · weather
├─ services/         axios 공통, 날씨, 대기질, 천문, NASA 이미지, 저장(IndexedDB)
├─ composables/      온도 단위, 등급, 차트 이미지
├─ constants/        지역, 별자리 모양, 종목, 사주 용어·규칙, 행운·뷰티 규칙,
│                    등급, 시연용 기본 프로필
└─ utils/            만세력, 사주 운세, 점성술 계산·운세, 통합, 날짜
```

### 컴포넌트 통신

| 방식 | 쓰인 곳 |
|---|---|
| Props (부모→자식) | `CategoryScoreCard` 종목 데이터, `DateNavigator` 선택 날짜, `RegionSelector` 현재 지역, `ZodiacConstellation` 별자리 모양 |
| Emits (자식→부모) | 날짜 변경, 지역 변경, 종목 상세 이동, 차트 이미지 변경·삭제 |
| Slot | `BaseDashboardCard` 가 제목·아이콘·본문·액션 영역을 슬롯으로 받아 모든 화면의 카드 껍데기로 쓰임 |
| 조건부 컴포넌트 | `ChartOrZodiacDisplay` 가 차트 이미지 유무에 따라 두 자식을 갈라 렌더링 |

상태는 화면 컴포넌트가 소유하지 않고 Pinia store 에 두어, 화면을 옮겨도 설정과 계산 결과가 유지됨.

### 공통 결과 모델

사주·별자리·통합이 같은 형태의 객체를 만들기 때문에 결과 컴포넌트를 그대로 재사용함. `type` 값으로 계산 기준을 구분함.

```js
{
  type: 'saju' | 'astrology' | 'integrated',
  date, totalScore, grade, headline,
  energy: { title, description, helpful[], cautions[], evidence[] },
  summary, outlook,
  categories: [{ key, label, score, sajuScore?, astrologyScore?, grade, description, evidence[] }],
  recommendedActions[], cautionActions[],
  lucky: { color: { name, hex }, number, direction, time, evidence },
  advice, basis[]
}
```

### 저장소

- `localStorage` — 사용자 설정 메타데이터
- `IndexedDB` — 출생 차트 이미지 Blob (형식·5MB 검증 후 저장, Object URL은 컴포넌트 소멸 시 해제)

만세력은 검산 스크립트로 대조함. 경계값(입춘 직전 출생, 야자시, 절입 당일)과 음력 윤달 케이스를 포함해 10건 전부 일치.

배포는 Vercel. `vercel.json` 의 rewrite 로 `/saju` 처럼 주소를 직접 입력하거나 새로고침해도 404 가 나지 않게 함.
API 키는 Vercel 환경변수로만 두고 저장소에는 `.env.example` 만 둠.

### 진행 내역

#### 1. Project Scaffolding

Vite로 프로젝트를 생성하고 HMR과 Vue Devtools 동작을 확인하는 단계.

- 생성 시 Router · Pinia · ESLint · Prettier · Devtools 옵션을 함께 선택해, 이후 단계에서 추가 설치 없이 이어가도록 구성
- `vite.config.js`에 `@` → `src` 별칭을 두어 깊은 상대경로(`../../`) 없이 import
- HMR은 `.vue` 파일의 template 수정 시 새로고침 없이 반영되는 것과, 터미널에 `hmr update` 로그가 찍히는 것으로 확인
- Devtools에서 확인한 것 — Components 탭에서 `WeatherHomeView → WeatherCard` 트리와 내려간 `cityItem` props 값, Pinia 탭에서 버튼 클릭에 따른 store state 변화, Router 탭에서 상세 이동 시 내비게이션 이력

#### 2. Weather Mockup

템플릿 문법만으로 정적 목업을 구성하는 단계. 배열 렌더링, 조건부 렌더링, 입력 바인딩, 이벤트 수식어가 핵심.

**구현**

- `v-for` + `:key="item.id"`로 날씨 카드 반복 렌더링
- 카드 클릭 시 상태 표시줄에 `{도시}이 선택되었습니다` 표시, 카드 안의 상세보기 버튼은 `@click.stop`으로 버블링을 끊어 카드 클릭이 함께 발동하지 않도록 처리
- 한글 입력 시 `v-model`이 IME 조합 중인 글자를 놓치는 문제가 있어, `:value="searchQuery"` + `@input="e => searchQuery = e.target.value"`로 바인딩 원리를 직접 구현

**커스텀**

- **기온 11단계 세분화** — 요구된 2단계(더움/선선함) 대신 체감을 세분화한 11단계 `v-if` / `v-else-if` / `v-else` 체인으로 확장

  | 기온 | 라벨 | | 기온 | 라벨 |
  |---|---|---|---|---|
  | -15℃ 미만 | 🥶 극심한 추위 · 한파경보 | | 15 ~ 20℃ | 🙂 온화함 · 활동하기 편함 |
  | -15 ~ -10℃ | 🧊 매우 추움 · 강추위 | | 20 ~ 25℃ | 🌤️ 따뜻함 · 늦봄·초여름 |
  | -10 ~ 0℃ | ❄️ 추움 · 한겨울 날씨 | | 25 ~ 30℃ | ☀️ 더움 · 여름 날씨 |
  | 0 ~ 5℃ | 🌬️ 쌀쌀함 · 겨울~초봄 | | 30 ~ 33℃ | 🔥 매우 더움 · 한여름 |
  | 5 ~ 10℃ | 🧥 서늘함 · 겉옷 필수 | | 33℃ 이상 | 🥵 폭염 · 극심한 더위 |
  | 10 ~ 15℃ | 🍃 선선함 · 봄·가을 | | | |

- **배지 색상 동적 바인딩** — 클래스명을 고정 문자열로 박지 않고 `:class` 배열 문법으로 11단계 각각의 색상을 적용. 한파(보라·남색) → 온화(초록·연두) → 폭염(주황·빨강)으로 이어지는 색 흐름을 직접 정의
- **데이터 필드 확장** — 도시명·기온·상태 외에 `humidity`(습도), `wind`(풍속) 추가. 극단 기온대 확인용으로 대관령(-18℃, 눈), 대구(34℃, 맑음) 데이터를 넣어 11단계 양끝을 검증
- **검색 기능 실동작화** — 검색어가 화면에 표시만 되던 것을, 도시명에 포함될 때만 카드가 보이도록 실제 필터링에 연결
- **날씨 상태 다중 체크박스 필터** — 맑음/비/구름/눈을 `ref([])` 배열에 `v-model`로 묶어 다중 선택. 검색어 필터와 AND 조건으로 결합되고, 결과가 없으면 안내 문구 표시

> `v-if`와 `v-for`를 같은 엘리먼트에 함께 쓰니 `v-if`가 먼저 처리되어 반복 변수를 읽지 못하는 문제가 있었음. `<template v-for>`로 감싸 해결했고, 다음 단계에서 `computed`로 정리됨.

#### 3. Weather Composition

목업 로직을 Composition API로 정리하는 단계. `computed`로 파생 상태를 만들고 `watch`·`watchEffect`로 변화를 감시하는 것이 핵심.

**구현**

- 검색어 필터링을 `filteredWeatherList` `computed`로 전환. 검색어가 비면 원본을 그대로 반환하고, 아니면 도시명 포함 여부로 필터링. 커스텀인 상태 필터도 같은 `computed` 안에서 함께 결합
- `watch`로 선택된 도시를(이전값·현재값 함께), `watchEffect`로 검색어를 감시해 콘솔에 로그

**커스텀**

- **최고/최저 기온 분리** — `tempHigh`·`tempLow`를 도시별 독립 값으로 추가하고 현재 기온 아래 줄에 별도 표기
- **감시 대상 확장** — 상태 필터와 즐겨찾기는 배열이라 얕은 비교로는 변화가 잡히지 않아 `{ deep: true }`를 붙여 감시
- **뷰티 연계 조언 3종** — 관심분야와 날씨를 엮은 이 앱의 핵심 컨셉. `uvIndex`·`rainfall` 필드를 추가하고 아래 기준으로 문구를 산출

  | 자외선 지수 | 조언 | | 시간당 강수량 | 조언 |
  |---|---|---|---|---|
  | 0~2 | 낮음 | | 0~1mm | 약한 비 |
  | 3~5 | 보통 · 선크림 권장 | | 1~3mm | 보통 비 · 장시간 외출시 장화 |
  | 6~7 | 높음 · 선크림 필수 | | 3~10mm | 강한 비 · 장화 착용 권장 |
  | 8~10 | 매우 높음 · 모자·양산 권장 | | 10~20mm | 매우 강한 비 · 적극 권장 |
  | 11 이상 | 위험 · 외출 자제 | | 20mm 이상 | 집중호우 · 외출 최소화·침수 주의 |

  풍속은 기존 표기 뒤에 괄호로 덧붙이는 방식 — 5m/s 미만 문구 없음 / 5~8 `(치마·모자 주의)` / 8~12 `(강풍 주의)` / 12 이상 `(매우 강한 바람 · 외출 시 주의)`

- **즐겨찾기 토글** — 카드 우측 상단 ⭐/☆ 버튼. 카드 클릭으로 버블링되지 않도록 `@click.stop` 적용

#### 4. Weather Component

한 파일에 몰려 있던 화면과 로직을 기능 변경 없이 컴포넌트로 분리하는 단계. props(부모→자식)와 emit(자식→부모) 흐름이 핵심.

| 컴포넌트 | 역할 |
|---|---|
| `WeatherParent` | 반응형 상태와 `computed`·`watch`·`watchEffect`를 모두 소유하는 최상위 |
| `BaseDashboardCard` | `<slot>` 하나로 검색·필터·리스트 영역에 공통 사용되는 카드 껍데기 |
| `SearchBar` | `currentQuery` props로 받고 `update-query` emit |
| `WeatherCard` | `cityItem` props로 받고 `select-card` · `click-detail` emit |

- `SearchBar`·`WeatherCard`는 템플릿상 `BaseDashboardCard`의 `<slot>` 안에 있지만 스크립트적으로는 부모 스코프에서 컴파일되므로 props·emit 통신이 그대로 성립. `BaseDashboardCard`는 데이터 흐름에 관여하지 않는 순수 시각 껍데기
- **커스텀** — 11단계 배지, 조언 문구, 즐겨찾기 등 표시 관련 로직을 `WeatherCard`가 소유하도록 이전. 표시 책임은 카드가 갖는 것이 자연스럽다고 판단

#### 5. Weather Router

앱을 여러 화면으로 나누는 단계. 지연 로딩, 동적 라우트, Catch-all, Programmatic Navigation이 핵심.

**구현**

- 하위 화면을 전부 `() => import(...)`로 지연 로딩해 초기 번들에서 분리
- 상세보기를 `window.alert`에서 `router.push('/weather/' + cityId)`로 전환하고, 상세 화면은 `useRoute()`의 `route.params.cityId`로 도시를 조회
- `/:pathMatch(.*)*` Catch-all로 잘못된 주소를 404 화면에 연결

**커스텀**

- **`/tips` 화면 추가** — 자외선·강수량·풍속 조언이 어떤 기준으로 나오는지 표로 정리한 별도 화면. 카드에 찍히는 문구의 근거를 사용자가 확인할 수 있게 함
- **404 화면 별도 구성** — 안내 문구와 대시보드 복귀 버튼
- **조언 로직 유틸 분리** — 카드에만 있던 조언 함수(`uvAdviceText` / `rainAdviceText` / `windSuffix`)를 `utils/weatherAdvice.js`로 빼서 카드와 상세 화면이 같은 로직을 공유하도록 정리

#### 6. Weather Store

전역 상태를 Pinia로 옮기는 단계. state·getter·action 구성과 Props Drilling 제거가 핵심.

| Store | state | getter | action |
|---|---|---|---|
| `configStore` | `unit`, `theme` | `unitSymbol`, `isDark` | `toggleUnit`, `toggleTheme` |
| `favoritesStore` | `cities` | `count` | `toggle`, `isFavorite` |
| `historyStore` | `viewedCities` | `hasHistory` | `recordView` |

**구현**

- 온도 단위 store와 `UnitToggler`를 만들어 내비게이션 바에 배치. 대시보드와 상세 양쪽에 단위 변환 적용
- 원본 온도는 항상 섭씨로 저장하고 표시 시점에만 `toDisplayTemp()`로 변환. 기온 11단계 분류는 표시 단위와 무관하게 **항상 원본 섭씨 기준**으로 계산해, 화씨로 바꿔도 "더움/폭염" 같은 분류가 흔들리지 않도록 함
- 대시보드에서 단위를 바꾸고 상세로 이동해도 선택한 단위가 유지되는 것으로 전역 상태 공유를 확인

**커스텀**

- **즐겨찾기를 store로 이전** — 이전까지 화면 로컬 `ref`라 상세에 갔다 돌아오면 초기화되던 것을 store로 옮겨 유지되게 수정. 카드가 store를 직접 참조하므로 `isFavorite` props와 `toggle-favorite` emit 릴레이가 통째로 사라짐
- **다크모드** — 새 store를 만들지 않고 `configStore`에 `theme`·`isDark`·`toggleTheme`를 함께 넣고 `ThemeToggler`를 내비게이션 바에 배치. 최상위 래퍼의 클래스를 토글해 전 화면 색상을 전환
- **최근 조회 도시** — 상세 화면 방문 시 도시명을 기록하는 store. 최신순 5개까지 유지되고 대시보드 하단에 표시

#### 7. Weather Axios

하드코딩 데이터를 실제 API 응답으로 대체하는 단계. 비동기 통신, 응답 매핑, 로딩·에러 처리가 핵심.

**구현**

- 응답을 기존에 쓰던 필드명에 그대로 매핑해, 이미 만들어둔 배지·조언·즐겨찾기·다크모드가 **수정 없이 재사용**되도록 함

  `main.temp` → `temp` · `main.temp_min/max` → `tempLow`/`tempHigh` · `weather[0].main` → `status`(영문을 맑음/비/구름/눈/흐림으로 매핑) · `main.humidity` → `humidity` · `wind.speed` → `wind` · `rain['1h']` → `rainfall`

- 대시보드는 5개 도시를, 상세는 여러 API를 `Promise.all`로 병렬 호출해 순차 호출 대비 로딩 단축
- API 키는 `.env`로 분리하고 커밋에서 제외. 형식만 담은 `.env.example`을 남겨 재현 가능하게 함

**커스텀**

- **대기오염 API 연동** — 미세먼지 등급(AQI 1~5)과 PM2.5·PM10을 가져와 **클렌징 조언**으로 연결. 1 좋음(별도 클렌징 불필요) / 2 보통(가볍게 세안) / 3 나쁨(마스크 + 꼼꼼한 클렌징) / 4 매우 나쁨(외출 자제 · 이중 세안) / 5 최악(외출 최소화 · 트러블 주의)
- **일출·일몰 연동** — OpenWeatherMap이 아닌, 키가 필요 없는 외부 API로 별도 조회. 일몰 이후에는 자외선 부담이 없다는 안내를 함께 표시
- **자외선 지수 폴백** — 무료·신규 발급 키에서 자외선 API가 막혀 있는 경우가 많아, 먼저 실제 호출을 시도하고 실패하면 **날씨 상태와 현지 시각 기반 추정치**로 대체. 야간은 0, 맑음/구름에 따라 기준값을 두고 정오에 가까울수록 강하게 보정
- **로딩·에러 UI** — 요청 중 안내 문구, 실패 시 원인(특히 신규 키의 활성화 지연)을 알려주는 메시지와 새로고침 버튼
- **필터 확장** — 실제 응답에는 목업에 없던 상태가 들어오므로 "흐림"을 필터 항목에 추가

**구현**

- 껍데기만 교체하고 구조는 유지. `BaseDashboardCard`는 `<slot>` 구조를 그대로 둬서 이 컴포넌트를 쓰는 부모 코드를 한 줄도 고치지 않음
- `SearchBar`도 IME 대응을 위해 `v-model`을 쓰지 않는 방식(`:model-value` + `@input`)을 유지해 단방향 데이터 흐름 보존

**커스텀**

- **11단계 배지 색상 유지** — `el-tag`로 바꾸되 직접 정한 11색은 그대로 살려, 라이브러리 컴포넌트와 커스텀 색상을 함께 사용
- **UX 요소 추가** — 직접 만들지 않았던 로딩 스켈레톤, 토스트 알림, 툴팁, 습도 게이지, 경로 표시를 라이브러리로 확보

#### 9. 외부 라이브러리 확장

시각화와 날짜 처리를 외부 라이브러리로 확장.

**Chart.js + vue-chartjs**

- **도시별 기온 비교 막대차트** — 대시보드에 표시 중인 도시들의 현재 기온을 한눈에 비교. 막대 색상은 11단계 배지와 **같은 기준(항상 원본 섭씨)** 으로 정해 카드와 색이 어긋나지 않게 함. 툴팁에 기온뿐 아니라 날씨 상태·습도까지 함께 표시
- **48시간 기온·강수확률 라인차트** — 3시간 간격 예보 API를 새로 붙이고 16개(≒48시간)만 잘라 과밀을 방지. 기온(℃/℉)과 강수확률(0~100%)은 단위가 달라 **이중 Y축**으로 분리하고, 강수확률은 점선으로 그려 구분

**Day.js**

- `utc` · `timezone` · `relativeTime` 플러그인과 `ko` 로케일 사용
- 일출·일몰 `오전 5:53` / 데이터 갱신 시각 `3분 전` / 차트 축 라벨 `24일 09시` / 툴팁 `8월 24일(일) 09시`로 포맷 통일
- 상대 시간이 멈추지 않도록 1분마다 갱신되는 값을 두고 `computed`가 이를 참조. 화면을 벗어날 때 타이머 정리

### 구현 노트

- **차트가 필터에 연동됨** — 막대차트는 검색어·상태 필터가 적용된 목록을 그대로 props로 받으므로, "대"를 검색하면 카드와 차트가 함께 대관령·대구만 남음. 앞 단계에서 만든 `computed` 하나가 카드와 차트를 동시에 구동
- **차트가 전역 상태에 반응함** — 차트 데이터와 옵션을 `computed`로 만들어 store의 단위·테마를 참조하게 함. 단위를 바꾸면 축 눈금이 `27℃ → 81℉`로, 다크모드를 켜면 격자·글자색이 함께 바뀜. 차트를 다시 그리는 코드는 따로 두지 않음
- **Chart.js는 쓰는 모듈만 등록해야 함** — tree-shaking 구조라 기본적으로 아무 요소도 등록되어 있지 않음. 라인은 `LineElement`·`PointElement`·`Filler`, 막대는 `BarElement`처럼 필요한 것만 `register()`
- **다크모드 이중 관리 해소** — Element Plus의 다크 테마는 `<html class="dark">` 기준이라, 직접 만든 다크모드와 어긋나 라이브러리 컴포넌트만 밝게 남는 문제가 있었음. store의 테마를 `watch`해 html 클래스를 함께 토글하도록 수정하고, 라이브러리가 관리하는 표면의 다크 스타일은 걷어내 중복을 제거
- **전역 CSS와의 충돌** — 공통 스타일이 `h1`~`h3` 색상을 하드코딩해 둬서 다크 배경에서 제목이 묻혔음. 전역 CSS를 건드리는 대신 다크모드일 때만 덮어쓰도록 처리
- **문자열 state를 스위치에 연결** — `el-switch`는 boolean을 다루는데 store의 state는 `'celsius'` / `'light'` 같은 문자열. store를 억지로 바꾸는 대신 **쓰기 가능한 `computed`**(get/set)로 연결
- **아이콘 전역 등록의 트레이드오프** — 편의를 위해 일괄 등록했으나 미사용 아이콘까지 번들에 포함됨. 필요한 아이콘만 개별 import 하는 편이 나음
